# 1단계 brief — QA

공통 규칙: `docs/upgrade/briefs/00-common.md` 를 먼저 읽습니다.

## 목표

지금 빌드의 **품질 기준선**을 잽니다. 2단계 구현이 무엇을 깨뜨렸는지 비교할 수 있게, 다시 돌릴 수 있는 점검 목록과 도구를 남깁니다.
결과물: `docs/upgrade/qa-baseline.md` (촬영 · 로그는 `docs/upgrade/qa/`).

## 할 일

1. **정적 검증** — `npm run lint` · `timeout 600 npx vitest run --reporter=verbose` · `npm run build` 결과(통과 수 · 경고 · 번들 크기).
2. **화면 흐름** — 타이틀 → 캐릭터 선택 → 맵 선택 → 게임 → 결과 → 다시 하기 / 처음으로. 1440×900 · 844×390 · 390×844 세 크기, 로컬(5310)과 라이브 둘 다.
   콘솔 오류 · 가로 넘침 · 잘린 UI · 키보드만으로 끝까지 가는지(포커스 표시 포함)를 봅니다.
3. **게임 플레이** — Playwright 로 키를 눌러 실제로: 이동 · 풍선 설치 · 바늘(X) · 아이템 획득 · 갇힘 → 탈락 · 승리 / 패배 / 무승부 각 결과. 맵 7종 + 랜덤 각각 한 판 이상은 띄워서 막힌 곳 · 겹침 · 이상한 블록이 없는지.
   README 에 「승리(win) 는 수동 확인 권장」으로 남아 있으니 **승리 화면을 실제로 띄워** 확인합니다(`?bots=` 등 활용).
4. **성능** — 데스크톱 기준 fps(rAF 간격으로 실측, 맵 · 봇 수 바꿔 가며), 첫 로딩 전송량 · 시간(라이브), 긴 판(5분 이상)에서 메모리 증가.
5. **휴대폰 실태** — 지금은 PC 전용(키보드)입니다. 터치 기기로 열면 무엇이 보이고 무엇을 할 수 없는지 정확히 기록합니다(2단계 터치 조작 설계의 근거).
6. **소리** — autoplay 잠금 해제 · 설정 토글 · 탭 전환 시 동작.
7. **접근성** — 대비(작은 글자 4.5:1), 포커스 순서, 축소 모션, 스크린리더로 읽히는 제목 · 버튼 이름.
8. **회귀 도구** — 위 점검 중 다시 돌릴 가치가 있는 것을 `docs/upgrade/qa/` 의 스크립트(예: `smoke.mjs`)로 남기고 실행법을 적습니다(2단계 뒤 같은 명령으로 비교). 스크립트는 레포 `src/` 를 건드리지 않고 URL 만 받습니다.
